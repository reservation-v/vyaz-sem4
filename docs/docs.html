Общее описание технологии

Коворкинг «Место»: сайт и приложение бронирования рабочих мест и переговорок. Технология включает веб-сайт, серверное приложение на Go, базу данных PostgreSQL и обмен новостями по RSS.

1.1 Назначение

Технология автоматизирует работу коворкинга «Место». Офис расположен на 31-м этаже башни «Око» в Москва-Сити.

Технология выполняет следующие функции:

  • показывает информацию о пространстве, тарифах, правилах и контактах;
  • принимает брони деск-мест, кабинетов и переговорок;
  • хранит клиентов и брони;
  • контролирует занятость пространства;
  • рассчитывает стоимость и депозит;
  • показывает свои и внешние новости;
  • публикует свою RSS-ленту;
  • ищет данные по сайту и по базе данных.

Объекты автоматизации:

  • офис и его пространства;
  • деск-места, кабинеты и переговорки;
  • клиенты: люди и команды;
  • брони с тарифом и депозитом;
  • новости и подключённые RSS-источники.

1.2 Общая схема технологии

Браузер запрашивает страницу у Go-сервера. Сервер вызывает сценарий, читает или записывает данные в PostgreSQL и отдаёт готовый HTML.

Внешние RSS-ленты читает сервер. Виджеты обращаются к внешним API напрямую из браузера.

Основные потоки данных:

  • браузер отправляет HTTP-запрос на сервер;
  • маршрут выбирает обработчик;
  • обработчик вызывает сценарий;
  • сценарий обращается к репозиторию;
  • репозиторий выполняет SQL-запрос;
  • PostgreSQL возвращает данные;
  • шаблон формирует HTML-страницу.

Шаблоны, стили, скрипты и миграции встроены в бинарник через embed. Поэтому для запуска нужен один исполняемый файл и база данных.

Миграции применяются при старте сервера. Если миграция завершается ошибкой, сервер не начинает работу.

Сайт

Сайт содержит главную страницу, тематические страницы и общее меню. Меню «Остальное тут» открывает список всех страниц. Поиск в шапке ищет по названиям страниц и ключевым словам.

На главной странице работают семь сервисов. Один сервис - собственное приложение бронирования. Остальные шесть - интеграции с внешними API.

Приложение бронирования

Приложение работает на странице /booking. Оно показывает краткую сводку базы данных, формы клиента и брони, поиск и таблицу броней.

Приложение поддерживает создание, редактирование и удаление клиентов и броней. Поиск работает по одному значению и по двум связанным значениям.

Приложение новостей

Страница /news объединяет свои новости из базы данных и материалы подключённых RSS-лент. У каждой новости указан источник.

Сервер отдаёт общую ленту в JSON по адресу /api/news. Свою ленту сервер публикует в формате RSS 2.0 по адресу /news/rss.xml.

XML-страница

Страница /residents загружает файл residents.xml. Скрипт строит таблицу, ищет по значениям тегов и сортирует строки.

База данных

База данных хранит пять таблиц бронирования и две таблицы новостей. Схема и начальные данные задаются миграциями.

Сервер

Сервер написан на Go. Он принимает HTTP-запросы, вызывает сценарии, применяет миграции и отдаёт HTML, JSON или RSS.

Внешние интеграции

Виджеты обращаются к внешним API из браузера. RSS-клиент работает на сервере. Такое разделение нужно потому, что браузерный запрос к чужой ленте может блокироваться политикой CORS.

Развёртывание

Локальная среда запускается через Docker Compose. На сервере работают два контейнера Podman: приложение и PostgreSQL. Службы systemd запускаются от пользователя.

1.4 Описание применения

Технологический процесс включает шесть шагов:

  1. Посетитель открывает сайт в браузере.
  2. Сервер отдаёт запрошенную страницу.
  3. Посетитель выбирает информацию или бронирование.
  4. Сервер проверяет введённые данные.
  5. База данных сохраняет запись.
  6. Сервер показывает результат операции.

Регламент работы:

  • сайт работает круглосуточно;
  • бронирования принимаются на текущую и будущие даты;
  • отмена брони выполняется удалением записи;
  • внешние RSS-ленты кэшируются на 5 минут;
  • резервное копирование выполняет администратор;
  • оператор проверяет брони и новости в рабочие часы.

Логика бронирования

Сценарий бронирования выполняет проверки по порядку:

  1. проверяет формат даты;
  2. проверяет, что дата не в прошлом;
  3. находит пространство и проверяет его активность;
  4. находит клиента;
  5. проверяет доступность тарифа для типа пространства;
  6. проверяет часы и длительность;
  7. рассчитывает цену и депозит;
  8. проверяет пересечения с другими бронями;
  9. сохраняет бронь в транзакции.

Периодные тарифы доступны только для деск-мест. Почасовой тариф доступен для всех пространств.

Сохранение брони защищено транзакцией. Репозиторий блокирует строку пространства командой SELECT ... FOR UPDATE. Затем он проверяет пересечения и вставляет запись. Это не даёт двум запросам занять одно и то же время.

Логика новостей

  • свои новости читаются из таблицы news;
  • активные источники читаются из таблицы news_sources;
  • сервер загружает ленты параллельно, не более 8 одновременно;
  • каждый источник кэшируется на 5 минут;
  • дубли удаляются по ссылке;
  • лента сортируется по дате публикации;
  • лимиты: 30 своих новостей, 12 с одного источника, 100 всего.

Логика поиска

Поиск по одному значению использует ILIKE по имени клиента, компании или названию пространства. Поиск по двум значениям принимает клиента и тип пространства.

SQL-запрос соединяет таблицы clients, bookings, spaces и space_types. Второй список типов сужается по выбранному клиенту.

Логика XML-страницы

Браузер загружает файл residents.xml. Скрипт разбирает XML, строит таблицу и выполняет поиск и сортировку без запросов к серверу.

Логика сводки

SQL-запрос считает количество офисов, типов, пространств, клиентов и броней. Он также считает подтверждённые брони, отменённые брони, выручку и самый популярный тип пространства.

2.4 Использование программы

Программу можно запустить тремя способами.

Локальный запуск через Docker Compose

make up

Команда собирает приложение и поднимает PostgreSQL. Сайт открывается по адресу http://localhost:8081/.

Остановка и очистка:

make down
make clean

Команда make clean удаляет контейнеры, том базы данных и локальный образ. Используйте её только для тестовой среды.

Локальный запуск без контейнера приложения

docker compose up -d db
DATABASE_URL='postgres://coworking:devsecret@localhost:49733/coworking?sslmode=disable' go run ./cmd/server

Сервер применит миграции и начнёт слушать порт 8081. Пароль devsecret задан в Makefile для локальной среды.

Сборка и проверка

3.1 Общее описание информационного обеспечения

Информационная база построена на PostgreSQL 18. База данных называется coworking. Приложение подключается к ней по строке DATABASE_URL.

Принципы организации базы:

  • реляционная модель с первичными и внешними ключами;
  • нормализация данных до третьей нормальной формы;
  • отдельные таблицы-классификаторы для типов пространств;
  • ограничения CHECK, NOT NULL, UNIQUE и FOREIGN KEY;
  • версионные миграции для схемы и начальных данных;
  • индексы для поиска броней и новостей.

Источники входных данных:

Объём базы растёт вместе с числом клиентов, броней и новостей. Точные прогнозы объёма в учебном проекте не заданы.

Назначение баз данных и наборов данных:

  • хранение каталога офиса и пространств;
  • хранение клиентов и их контактов;

  • хранение собственных новостей;
  • хранение реестра RSS-источников;
  • обеспечение поиска, сводки и контроля целостности.

Режим обновления данных:

  • каталог обновляется миграциями;
  • клиенты и брони обновляются при операциях на сайте;
  • новости обновляются при публикации;
  • источники обновляются при подключении или отключении;
  • внешние новости не сохраняются в базе и загружаются по запросу.
